# Memory Bank local v0 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Native execution in this chat is recommended. The user requested inline implementation on 2026-10-27.

**Goal:** Run the first local case-to-brief flow with Supabase, real model calls, and inspectable citations.

**Architecture:** One Next.js application uses Supabase Auth and Postgres. Application services prepare evidence before an AI SDK agent runs. The same retrieval services serve initial retrieval and the agent tools.

**Tech stack:** Next.js App Router, TypeScript, Node.js 24, npm, shadcn/ui, React Hook Form, Zod, Supabase, AI SDK 7, Vitest, pgTAP, and Playwright.

**Spec:** [Memory Bank MVP design](../specs/2026-10-27-memory-bank-design.md).

## Global constraints

- Preserve structured input, two fixed templates, one demo workspace, and cross-domain retrieval.
- Use `AGENTS.md` and the contracts in `docs/reference/system-contracts.md`.
- Apply a 90-second total deadline, six reasoning steps, 12 tool calls, and one optional planner or repair call each.
- Keep at most 40 candidate sections and 12 context sections within 8,000 estimated tokens.
- Keep the planner off until a measured comparison supports enabling it.
- Provision real local Supabase before repository adapters. Configure model access before the first live analysis. Runtime mocks are excluded.
- Use the official starters and SDK APIs. Keep npm as the only package manager.
- Pin the Supabase CLI dev dependency to `2.122.0`. Use `npx supabase` rather than the older global CLI.
- Use the native runtime with experimental stack enabled. Read actual endpoints from JSON output. Docker is not a prerequisite.
- Tasks 1–6 deliver local v0. Task 7 completes the full challenge evaluation.

## Review focus

- A forged workspace ID must not expand access. Task 2 tests membership and RLS.
- Editing or archiving a case during analysis must preserve revision identity and exclude invalid new evidence. Tasks 3 and 4 test this.
- A failed query must not become an empty result. Task 4 tests both states.
- A planner response must not change a hard constraint. Task 5 tests the planning boundary.
- A hanging model call must end at the total deadline and release the run lease. Task 5 tests abort and cleanup.

## File boundaries

`src/app` owns routes and pages. `src/components/ui` contains shadcn components. Domain code lives in `src/modules`. Official clients and configuration live in `src/lib`. SQL lives in `supabase/migrations` and `supabase/tests`. The evaluation corpus lives in `evals`.

Only create files named in the current task or files required by the framework starter.
