# MVP Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a public Vercel demo where a reviewer can capture past cases with less effort and ask a new request to learn how similar cases went and what differs this time.

**Architecture:** Keep the single Next.js app, Supabase database, and one AI SDK agent. Add a non-persistent case draft step in `src/modules/cases`, change the agent's answer instructions, replace the seed corpus with one company storyline, and add a hosted profile with demo sign-in and a reset RPC. No new tables, no file parsing, no new agents.

**Tech Stack:** Next.js 16 App Router, TypeScript, Node.js 24, AI SDK 7, Supabase (Auth, Postgres 17, pgvector), Zod 4, React Hook Form, shadcn/ui, Vitest, pgTAP, Playwright, Vercel Hobby.

**Spec:** [Text-first knowledge agent](../specs/2026-10-29-text-agent-design.md). Scope decisions were agreed in conversation on 2026-10-30 and are recorded in the spec.

## Global Constraints

- Reviewers receive the GitHub repository and a Vercel link. They use the demo without a live presenter.
- All UI copy, corpus content, suggested prompts, and agent answers are in English.
- Vercel Hobby with Fluid Compute and Node.js 24. No Pro trial, no Edge runtime. Both analysis routes keep `maxDuration = 300`.
- Hosted run deadline is 240 seconds (`executionLimits.hostedDeadlineMs = 240_000`), synthesis reserve stays 60 seconds. Local deadline stays 300 seconds.
- Case drafting uses one structured-output model call with no tools, a 30-second deadline, and no persistence. Only an explicit Save creates a revision.
- Document files selected in Import stay in the browser. Nothing is uploaded or parsed. The UI labels this "Document parsing — coming soon".
- No in-app rate limit. Cost is bounded by a hard spending limit on a dedicated OpenAI project and the existing `concurrentRuns: 2` quota.
- Public sign-up stays disabled. Demo sign-in uses server-only `DEMO_EMAIL` and `DEMO_PASSWORD`.
- `npm run dev` does not seed cases. It prints App, Studio, and API URLs read from CLI JSON output, never secrets.
- Limits live only in `src/lib/contracts/limits.ts`. Docs link there instead of repeating values.
- Logs carry request IDs, counts, timings, error codes, and usage. They never carry case text, draft text, or secrets.

## Review Focus

- A reviewer pastes Vietnamese, messy, or very long notes into Import → the draft is English, over-limit text gets a 400 with the limit, nothing crashes.
- Notes that never state a result → the draft outcome is `unknown` with an empty observed outcome, never an invented success.
- A question with no recorded precedent → the answer says no recorded case matched after a successful search and does not fill "How similar cases went" with general advice.
- Hosted deployment without `DEMO_EMAIL`/`DEMO_PASSWORD` → the demo button is hidden and the demo route returns 404, the normal login still works.
- `demo:reset` run against the wrong target → it refuses unless the workspace ID and name match the demo workspace, and it never touches seed cases or users.
